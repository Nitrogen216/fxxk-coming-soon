## Instructions

Execute these steps in order. If any mandatory step fails, stop and report to the user — do NOT proceed.

### Step 1: Verify the 5 Stage-1 documentation files

These MUST exist (generated by `PAPER_TO_CODE_PROMPT.md` via an LLM in Stage 1):

1. `PROJECT_STRUCTURE.md`
2. `IMPLEMENTATION_PLAN.md`
3. `DATA_AND_EVAL.md` — must contain a `## Paper Target Metrics` YAML block
4. `RISKS_AND_NOTES.md`
5. `CLAIMS_AND_GATES.md` — must contain a `baseline_metrics:` YAML block

For each missing file: tell the user "Missing `<file>` — run `PAPER_TO_CODE_PROMPT.md` with your paper first, then save the 5 generated files to the project root." Then STOP.

### Step 2: Verify framework files

These MUST exist (copied from fxxk-coming-soon repo):

1. `AGENT_LOOP_PROMPT.md` (loop controller)
2. `CLAUDE.md` (project guidance, copied from `templates/project-CLAUDE.md`)

If either is missing, tell the user: "Missing `<file>` — copy it from fxxk-coming-soon/`<source path>` to project root." Then STOP.

If `LOOP_STATE.md` does NOT exist OR `--force-reset-state` is in `$ARGUMENTS`:

If `LOOP_STATE.md` already exists and `--force-reset-state` is NOT set: skip this step and keep the existing state.

### Step 4: Sync baseline_targets from CLAIMS_AND_GATES.md → LOOP_STATE.md

Unless `--skip-baseline-sync` is in `$ARGUMENTS`:

1. Parse `CLAIMS_AND_GATES.md` for the `baseline_metrics:` YAML block under `## Baseline Definition → Baseline Targets (M1 gate)`.

2. Extract each metric's `name` and `value` into a dictionary:
   ```yaml
   # e.g.
   baseline_targets:
     accuracy: 0.762
     f1_score: 0.701
   ```

3. Update `LOOP_STATE.md` → `milestones.M1_baseline.baseline_targets` with this dictionary. Use `Edit` tool to replace the `baseline_targets: {}` line.

4. If `CLAIMS_AND_GATES.md` has placeholder values (still shows `~` or `[...]`): warn the user "CLAIMS_AND_GATES.md still has placeholder values for `baseline_metrics`. Edit it with real numbers from the paper, then re-run `/init-project --skip-baseline-sync=false`."

### Step 5: Validate Paper Target Metrics YAML in DATA_AND_EVAL.md

1. Confirm `DATA_AND_EVAL.md` contains a YAML block under `## Paper Target Metrics` with `primary_metrics:` populated (not placeholder `~`).

2. If the block is empty or all `value:` fields are `~`: warn the user "Paper Target Metrics YAML in DATA_AND_EVAL.md has no real values. The loop cannot determine success without paper numbers. Fill these in before running `/reproduce`."

### Step 6: Create required directories

```bash
mkdir -p logs results data/raw data/processed configs
```
